# ClipboardProtector

[English](README.en.md) · 中文

<img src="app/assets/clipboard-protector.svg" width="96" alt="ClipboardProtector 图标">

查看哪些程序在访问 Windows 剪贴板，并按规则允许、阻止或询问。支持 BTC / ETH / SOL 地址替换检测。

**当前版本：0.1.0-alpha（开发预览）。** 建议先在独立的 Windows 测试环境体验。全局注入的长期稳定性，以及重启后的自启行为尚未完成验证，详见 [当前验证情况](doc/validation.md)。

[使用参考](doc/manual.md) · [构建和测试](doc/development.md) · [更新记录](CHANGELOG.md) · [贡献说明](CONTRIBUTING.md) · [安全报告](SECURITY.md)

## 能做什么

- **访问记录**：查看已接入保护的程序何时读取或写入剪贴板，支持日志筛选和 CSV 导出。
- **自定义规则**：按进程、读写操作、数据格式、内容来源和文本内容匹配，选择允许、阻止或询问，并配置通知。
- **地址保护**：识别纯地址和段落内的 BTC / ETH / SOL 地址替换；开启后，相关日志隐藏原文和内容哈希。
- **保护范围**：通过“开启保护”覆盖兼容的桌面程序；x64 主程序配套提供 32 位保护组件。开发者仍可通过环境变量指定单进程测试。
- **日常操作**：支持复制/粘贴快捷键授权、系统托盘和配置保存。
- **界面语言**：通过“选项 → 语言 / Language”选择中文或 English，即时切换并记住选择。
- **私有剪贴板**：用独立快捷键将选中文字存入程序内存，再写入目标输入框，内容不进入系统剪贴板。

## 获取与运行

运行环境为 **Windows 10/11 x64**。预览包发布后可从本仓库的 **Releases** 页面下载；尚无发布包时，可按 [构建说明](doc/development.md) 从源码构建。请完整解压 ZIP，保持主程序、DLL 和辅助程序在同一目录。

1. 在测试环境启动 `ClipboardProtector.exe`。发布构建会请求管理员权限；当前预览包未进行代码签名。
2. 从“保护 → 开启保护”启动保护，等待状态更新。菜单会随状态切换为“关闭保护”。
3. 配置规则，使用虚构内容检查允许、阻止和日志记录。需要地址替换检测时，再在设置中开启 Crypto 地址保护。
4. 测试结束后选择“保护 → 关闭保护”，或通过“窗口 → 退出”/托盘菜单退出程序。点击主窗口关闭按钮只会隐藏到托盘。

设置中的“打开后自动保护”控制下次及以后打开程序时是否自动开启保护，默认关闭；它与“随 Windows 开机自动启动”是两个独立选项。全局覆盖和自启相关验证仍应在带快照的 VM 中进行。

配置保存在 `%APPDATA%\ClipboardProtector\config.json`。升级时先退出旧程序，再整套替换配套文件。删除程序前先停用开机自启、退出程序；如不再需要配置，可另行删除上述配置目录。

## 私有剪贴板

程序运行时，在其他应用中选中文字，按 `Alt+Shift+C` 保存到私有内存；切换到目标输入框后按 `Alt+Shift+V` 写入。复制和粘贴的目标进程都必须已注入新版保护模块并确认就绪，通常需先开启保护。通过 **选项 → 设置快捷键** 统一设置私有复制、私有粘贴和“仅允许复制 / 粘贴快捷键”的模式切换组合键（默认 `Ctrl+Alt+F9`），保存后立即生效；**选项 → 清空私有剪贴板** 可随时清除内容，退出程序也会清空。

程序先与目标进程建立私有会话，再发送带标记的 Ctrl+C / Ctrl+V；被注入的模块在这次按键处理期间提供私有剪贴板，文字通过临时内存映射传回，不清空或暂存系统剪贴板。首版支持文字和多行内容，不保留富文本、图片或文件。未注入或未确认就绪时，不发送按键；新复制失败会清空旧内容。

若按键已发送但操作没有完整结束，目标进程会继续隔离剪贴板，阻止迟到的写入；可继续尝试私有操作，**恢复该进程的普通复制粘贴需要重启目标应用**。该方式适用于目标进程内经过已拦截 Win32/OLE 接口的复制粘贴；自定义异步消息循环、跨进程代理和绕过这些接口的实现不保证兼容，不能把“已注入”理解为覆盖所有复制通道。
私有内容不写入配置、访问日志或剪贴板历史。这可避免被系统剪贴板读取工具获取，但不防范键盘监听、进程内存读取或目标应用自身保存内容。

## 保护边界和隐私

本工具通过 DLL 注入和 Microsoft Detours 拦截剪贴板 API，**仅约束实际加载当前 Hook DLL 的进程**。Windows 受保护进程、UWP/AppContainer 和绕过这些 API 的访问可能不在覆盖范围内。涉及转账时，仍应核对最终粘贴的地址。

注入与卸载可能影响目标程序稳定性，当前版本尚不适合作为关键业务的唯一保护手段。

文本预览默认开启，可能将剪贴板前缀保留在内存日志中；CSV 导出、通知和询问窗口也可能包含敏感信息。图片/文件快照默认关闭。提交截图或 issue 时请使用虚构数据，并移除个人信息。

## 从源码构建

需要 Git、Visual Studio 2022 / Build Tools（安装 C++ 桌面开发工具）、Windows SDK 和 CMake 3.20+。开发构建及测试命令见 [构建和测试](doc/development.md)。

在通过 Git 克隆的仓库根目录运行以下命令，可依次构建 Win32/x64 组件，生成不含测试工具的预览包：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package-release.ps1
```

输出位于 `dist/`，包含 ZIP 和 SHA-256 校验文件。编译产物统一放在 `build/`；正式程序位于 `build/release/x64/bin/Release/`。脚本默认要求工作区没有未提交改动；试打包和发布步骤见 [发布指南](doc/publishing.md)。
